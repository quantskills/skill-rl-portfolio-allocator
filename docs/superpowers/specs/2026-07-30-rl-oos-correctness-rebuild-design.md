# RL 组合权重优化器：样本外正确性重构设计

**Skill 名**：`skill-rl-portfolio-allocator`  
**日期**：2026-07-30  
**类型**：research-correctness / reward / state / execution / validation  
**状态**：设计已确认，待实施计划  
**取代范围**：本设计取代 `2026-07-28-rl-reward-rescale-design.md` 的奖励与验收方案，并修正主设计中“DSR 必须作为训练主奖励”和“单次时间切分足以验证”的决策。未明确取代的资产池、因子集、成本模型和双模式目录结构继续有效。

---

## 1. 背景和证据

2026-07-28 运行完整流水线后，主回测结果为：

| 策略 | ARR | Sharpe | MDD | Calmar |
|---|---:|---:|---:|---:|
| PPO RL | -15.68% | -0.65 | -78.56% | -0.20 |
| 等权 | +6.44% | +0.33 | -34.01% | +0.19 |
| 纯多头 Top-N | -11.91% | -0.43 | -73.13% | -0.16 |
| 静态因子等权 | -19.11% | -0.76 | -81.68% | -0.23 |

现有 `research_ok=True` 只表示 RL 的 Sharpe 和 Calmar 高于静态因子等权，不表示策略绝对有效或优于最强基准。

对保存的 `backtest.zip` 与同 seed、同结构、未训练 PPO 进行诊断：

| 区间 | 训练后 PPO NAV | 未训练 PPO NAV | 训练后日均净收益 | 未训练日均净收益 |
|---|---:|---:|---:|---:|
| 训练期 | 3.08 | 0.43 | +4.70 bps | -1.76 bps |
| 样本外 | 0.38 | 1.05 | -5.63 bps | +1.08 bps |

训练后策略网络相对初始化发生显著变化，说明 PPO 完成了优化；但训练期改善没有泛化。样本外策略约有 +2.08 bps/日毛收益，却承担约 7.70 bps/日成本，最终净收益为 -5.63 bps/日。训练期 DSR 标准差约 1.175、范围约 -7.5 至 +21.1，而净收益标准差约 0.016，说明 DSR 尺度支配了直接收益。

状态诊断还发现：

- `factor_ic` 六维全部硬编码为零；
- 主回测和生产训练使用全零指数收益，`market_vol_20` 恒为零；
- `avg_corr_20` 与 `avg_corr_60` 是同一个当日值；
- 因子 exposure 未在矩阵运算前清理 NaN，可能整维退化为零；
- 训练没有实际使用验证环境、最佳 checkpoint 或早停；
- 只运行一个 seed，且没有保存 PPO 学习诊断曲线。

因此本轮目标不是继续增加 timesteps，而是重建可验证的研究闭环。

## 2. 目标

1. 让训练奖励具有稳定、可解释的尺度，并直接优化扣除全部成本后的收益。
2. 向策略提供严格因果、非退化、可在生产复现的因子有效性和市场状态。
3. 在组合构造层控制不连续排名引起的交易抖动，使微弱毛收益能够保留为净收益。
4. 使用多窗口、多 seed、带验证集的 walk-forward 研究流程；只有通过明确门槛的模型才能生成生产配置。
5. 保留简单模型作为强制 hurdle。PPO 若不能稳定击败静态权重和滚动 IC 策略，应停止生产部署，而不是继续堆叠 RL 复杂度。

## 3. 非目标

- 本轮不新增量价因子，不改变 CSI300 股票池。
- 不直接让 PPO 学习股票权重或总多空敞口。
- 不用测试窗口做超参数选择、early stopping 或模型选择。
- 不以单次回测、单一 seed、单一压力期胜负证明策略有效。
- 不承诺正收益；研究失败必须被如实报告并阻止生产模型更新。

## 4. 方案一：稳定奖励

### 4.1 决策

训练主奖励改为扣除全部显性成本后的日净收益。原始 DSR 从训练奖励中移除，只保留为离线诊断指标。

默认训练奖励：

```text
scaled_net_t = 100 × net_return_t

reward_t = clip(
    scaled_net_t
    - λ_dd × positive_drawdown_increment_t
    - λ_conc × concentration_excess_t
    - λ_to × turnover_excess_t,
    -5,
    +5
)
```

定义：

```text
positive_drawdown_increment_t = max(0, drawdown_t - drawdown_{t-1})
concentration_excess_t        = max(0, HHI_t - HHI_TARGET)
turnover_excess_t             = max(0, turnover_t - TURNOVER_BUDGET)
```

`net_return_t` 已扣佣金、印花税、冲击成本和融券费。额外换手项只惩罚超过硬预算后的部分，避免无条件重复计算交易成本。

初始实验中必须保留三个固定对照：

- A：`100 × net_return_t`，不加任何软惩罚；
- B：净收益加超限惩罚，即生产候选；
- C：旧 DSR 复合奖励，仅用于证明重构是否改善，不得作为默认候选。

只有 B 在验证窗口稳定优于 A 时，软惩罚才进入最终模型。否则使用 A，并依赖组合构造层的硬约束。

### 4.2 DSR 处理

`DSRState` 可继续存在，但用途限定为：

- rollout 后的风险调整诊断；
- reward 分布对照；
- 研究报告中的辅助指标。

DSR 不进入 PPO 梯度。后续若重新研究 DSR，必须作为独立实验，具备 warm-up、有限方差保护、裁剪和完整消融，不能直接恢复为默认奖励。

### 4.3 配置

新增或调整以下配置：

```text
REWARD_SCALE=100.0
REWARD_CLIP=5.0
HHI_TARGET=0.03
TURNOVER_BUDGET=0.20
LAMBDA_DRAWDOWN=0.5
LAMBDA_CONCENTRATION=0.5
LAMBDA_TURNOVER=0.05
```

`HHI_TARGET=0.03` 略高于 30 多头、15 空头近似等权组合的理论 HHI，允许正常权重差异，只惩罚明显集中。验证阶段只比较三个预先固定的惩罚组合：

```text
none:   λ_dd=0.0, λ_conc=0.0, λ_to=0.00
low:    λ_dd=0.5, λ_conc=0.5, λ_to=0.05
medium: λ_dd=1.0, λ_conc=1.0, λ_to=0.10
```

默认配置为 `low`。不进行无边界超参数搜索，测试集不得参与选择。

### 4.4 验收

- 训练 rollout 的 reward 标准差处于 0.5 至 2.0。
- reward 绝对值的 99.9% 分位不超过 5。
- 任一步骤的绝对 reward 不得超过 episode 累计绝对 reward 的 1%。
- reward 与同日净收益方向一致；正净收益在约束相同时必须产生更高 reward。
- A/B/C 的相同数据、seed 和训练预算对照结果必须落盘。

## 5. 方案二：严格因果的市场与因子状态

### 5.1 状态数据层

新增独立的每日 `market_state` 数据集。它在训练前预计算，训练、验证、测试和生产共享同一套字段定义。每个日期 `t` 的记录只能依赖 `t` 日收盘前已知的数据。

推荐字段：

| 类别 | 字段 |
|---|---|
| 市场状态 | CSI300 20/60 日收益、波动率、回撤、波动率历史分位 |
| 因子有效性 | 每个因子的 20/60 日 IC 均值、ICIR、正 IC 比率 |
| 因子收益 | 每个因子多空组合过去 20/60 日净收益与波动率 |
| 因子相关性 | 因子收益序列的 20/60 日平均相关性 |
| 组合状态 | 上期因子权重、20/60 日组合波动率、回撤、近期换手 |

### 5.2 IC 的因果定义

在日期 `t` 构建状态时，最新允许使用的 IC 是：

```text
IC_{t-1} = Spearman(F_{t-1}, return_t)
```

因为 `F_{t-1}` 和 `return_t` 在 `t` 日收盘后均已知。禁止使用：

```text
Spearman(F_t, return_{t+1})
```

作为 `t` 日状态。滚动 20/60 日 IC 只能由已经完成结算的 IC 序列构成。

### 5.3 状态实现要求

- `backtest.py`、`stress_test.py` 和 `allocate.py` 必须传入真实 `index_returns.parquet`。
- 删除 `factor_ic = zeros(K)` 占位实现。
- 因子 exposure 计算前对因子矩阵逐元素执行有限值清理。
- 20 日和 60 日相关性必须来自不同历史窗口，不能复制同一数值。
- 状态字段名、顺序、维度和 dtype 由一个 schema 定义，环境不得自行拼接隐式顺序。
- 训练集拟合 observation 标准化器；验证、测试和生产只读并冻结该标准化器。
- checkpoint 必须与状态 schema 版本及标准化参数绑定。schema 不一致时拒绝加载。

### 5.4 因果与数据质量测试

- 修改 `t+1` 及以后数据，不得改变日期 `t` 的状态。
- 每个字段报告非空率、有限值率、零值率、均值、标准差和分位数。
- 除明确设计的状态外，不允许全区间恒为零或恒定字段。
- 训练和测试分布漂移必须落盘；严重超出训练分布的字段产生告警。
- 在生产推理中，同一截止日期和 checkpoint 必须生成确定性一致的状态与动作。

## 6. 方案三：在组合构造层控制换手

### 6.1 决策频率

默认将因子动作和股票组合再平衡频率改为每周一次。非再平衡日保持上一目标持仓，仅处理无法交易、退市等强制事件。

每日换仓版本保留为对照，不作为默认生产候选。

### 6.2 持仓缓冲区

使用 entry/exit buffer 减少 Top-N 边界抖动：

```text
多头：
  新进入前 30 才买入
  已持有股票跌出前 45 才卖出

空头：
  新进入后 15 才开仓
  已持有股票离开后 30 才平仓
```

当持仓数不足时，按排名补足；停牌股票继续执行冻结规则。缓冲阈值通过验证集选择，但候选集合必须预先固定。

固定候选集合为：

```text
tight:   多头 30/40，空头 15/25
default: 多头 30/45，空头 15/30
wide:    多头 30/60，空头 15/45
```

每组数字分别表示 entry/exit 排名阈值；默认使用 `default`。

### 6.3 硬换手预算

目标股票权重生成后，执行确定性投影：

```text
sum(abs(projected_w_t - w_{t-1})) <= TURNOVER_BUDGET
```

默认每次再平衡预算为 0.20。投影后必须重新检查：

- 多头名义不超过 1.0；
- 空头名义不超过 0.30；
- 停牌持仓不发生交易；
- 权重均为有限值；
- 投影不会改变原始多空方向。

### 6.4 因子动作稳定性

PPO 改为输出相对上期因子权重的增量，单维默认限制：

```text
abs(delta_factor_weight_i) <= 0.10
```

增量应用后再执行 L1 归一化。EMA 可继续保留，但它是动作平滑工具，不替代股票组合的换手预算。

### 6.5 成本敏感性

每个样本外结果都必须报告：

- 毛收益；
- 佣金、印花税、冲击、融券成本分项；
- 净收益；
- 成本为默认值的 0.5 倍、1 倍和 2 倍时的结果。

验收门槛：

- 样本外年化换手不超过 12 倍；
- 默认成本下，佣金、印花税和冲击的年化拖累合计不超过 3%，包括融券费的总年化成本拖累不超过 5.5%；
- 净收益至少保留毛收益的 60%；
- 2 倍成本下合并样本外 Sharpe 仍大于零。

若降换手后毛收益消失，应判定原策略收益主要来自不可交易的排名抖动，不允许通过降低成本假设挽救结果。

## 7. 方案四：Walk-forward 验证和研究门槛

### 7.1 窗口设计

默认采用扩展训练窗口，每个研究单元包含互不重叠的训练、验证和测试段：

| Fold | 训练 | 验证 | 测试 |
|---|---|---|---|
| 1 | 2005–2012 | 2013–2014 | 2015–2016 |
| 2 | 2005–2016 | 2017–2018 | 2019–2020 |
| 3 | 2005–2020 | 2021–2022 | 2023–2024 |

具体边界按实际交易日调整。每个 fold 固定运行 seed `[0, 1, 2, 3, 4]`。验证段用于超参数、训练步数、early stopping 和 checkpoint 选择；测试段只在该 fold 设计冻结后运行一次。

压力测试继续独立运行，不替代常规 walk-forward。

### 7.2 强制基准

每个 fold 必须包含：

1. 股票池等权；
2. 静态因子等权；
3. 仅使用训练段估计的静态最优因子权重；
4. 滚动 IC 加权策略；
5. 未训练 PPO，作为学习有效性诊断；
6. PPO 候选模型。

PPO 的研究价值是相对于简单动态和静态方法的增量，而不是只超过最弱基准。

### 7.3 训练诊断和模型选择

训练必须保存：

- rollout reward、episode return；
- policy loss、value loss、entropy、approx KL、clip fraction；
- explained variance；
- 动作均值、标准差、边界饱和率；
- 因子权重时间序列；
- 验证集净收益、Sharpe、MDD、换手和成本；
- 最佳 checkpoint 对应的选择依据。

`EvalCallback` 必须实际连接验证环境。验证环境与训练环境使用不同时间段，但共享训练段拟合的状态标准化器。不得按训练 reward 选择最终 checkpoint。

### 7.4 `research_ok` 门槛

`research_ok` 改为具名 gate 列表。所有硬门槛通过时才返回 `True`：

```text
combined_oos_arr > 0
median_seed_oos_sharpe > strongest_baseline_sharpe + 0.10
positive_excess_return_folds >= 2 / 3
median_seed_excess_return > 0
abs(oos_mdd) <= abs(strongest_baseline_mdd) + 0.05
annualized_turnover <= 12
cost_2x_oos_sharpe > 0
no_leakage_tests_passed
state_quality_tests_passed
```

报告必须列出每项 gate 的阈值、实际值和通过状态。任何 gate 缺少数据时按失败处理，不得默认为通过。

“最强基准”由该 fold 验证段确定，并在测试段冻结。不得在看到测试结果后更换比较基准。

### 7.5 生产发布门槛

只有研究版本通过全部硬门槛后，`allocate.py --retrain` 才允许覆盖生产 checkpoint 和 allocations。失败时：

- 保留上一个已批准的生产产物；
- 保存失败研究报告；
- 退出码非零；
- 不以“比另一个亏损策略更好”为理由继续发布。

## 8. 数据流和组件边界

```text
原始量价 / CSI300 指数
          │
          ├── features.parquet
          └── market_state.parquet
                    │
          因果检查 + 状态质量检查
                    │
      ┌─────────────┴─────────────┐
      │                           │
训练窗口                     验证窗口
拟合 observation scaler       冻结 scaler
训练 PPO                     选择 checkpoint / 早停
      └─────────────┬─────────────┘
                    │ 设计冻结
                 测试窗口
                    │
       基准比较 + 成本敏感性 + gates
                    │
             research_ok?
              │           │
             否           是
       阻止生产更新    全数据重训生产模型
```

职责边界：

- `features.py`：个股因子，不负责训练状态。
- 新的状态构建模块：生成严格因果的 `market_state` 和 schema。
- `env.py`：消费已经定义的状态、执行动作、结算净收益，不在内部临时估计未来依赖统计量。
- `portfolio.py`：持仓缓冲、换手投影和硬约束。
- `train.py`：训练、验证 callback、日志和 checkpoint。
- `backtest.py`：fold 编排、基准、指标、gate，不自行伪造指数或状态。
- `allocate.py`：只加载已批准方法和全量数据重训；发布前检查研究批准记录。

## 9. 错误处理

- 状态 schema、scaler 或 checkpoint 版本不匹配：立即失败。
- 指数数据缺失或状态字段退化：研究 gate 失败，不以零值代替。
- fold 数据不足：明确报告该 fold 跳过；硬门槛所需 fold 数不足时整体失败。
- 某 seed 训练出现 NaN、动作全饱和或验证 reward 异常：该 seed 计为失败并保留日志。
- 成本或换手约束投影失败：环境 step 失败，不静默缩放为未知状态。
- 生产 gate 失败：不覆盖旧 checkpoint 和 allocations。

## 10. 测试策略

### 单元测试

- reward 公式、尺度、裁剪和方向；
- 新增回撤而非回撤水平的惩罚；
- IC 的 `t-1 → t` 对齐；
- 状态 schema、有限值和标准化冻结；
- entry/exit buffer；
- 换手预算投影和多空约束；
- gate 缺失数据按失败处理。

### 因果测试

- 未来数据扰动不改变当前特征、状态、动作；
- 验证和测试 scaler 不调用 `fit`；
- 测试段数据不进入 checkpoint 选择。

### 集成测试

- 小型合成数据完成 train/validate/test；
- 相同 seed 和数据产生可重复结果；
- 验证 callback 保存最佳 checkpoint；
- gate 失败时不覆盖生产文件；
- 0.5 倍、1 倍和 2 倍成本回测均可复现。

### 研究验收

- 运行三个 walk-forward folds、五个 seeds 和全部基准；
- 输出合并及逐 fold 指标；
- 输出 reward、动作、状态、换手和成本诊断；
- 所有硬 gate 通过后，才能声明研究成功。

## 11. 实施顺序

1. 先实现新的 walk-forward 结果结构和 gate，使失败能够被正确识别。
2. 替换奖励并完成 A/B/C 消融。
3. 构建因果 `market_state`、状态 schema 和冻结标准化器。
4. 增加每周再平衡、持仓缓冲和硬换手投影。
5. 完成多 seed walk-forward 与成本敏感性研究。
6. 只有研究门槛通过后，才连接生产发布保护。

每一步必须保留前一步的可运行基准，以便判断改善来自哪项改动。不得把四类改动一次性合并后只跑一次最终回测。

## 12. 完成定义

本设计的工程实现完成，不等于策略研究成功。完成必须分成两个状态：

### 工程完成

- 所有单元、因果和集成测试通过；
- 训练、验证、测试、生产职责分离；
- 报告和 gate 可复现；
